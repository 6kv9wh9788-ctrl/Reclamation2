# Reclamation prototype setup

## Run the autonomous hauling lab

1. Open the project with Unity `6000.3.24f1`.
2. Wait for script compilation to finish.
3. Choose **Reclamation > Create Autonomous Hauling Lab** from the Unity menu.
4. Open `Assets/Scenes/AutonomousHaulingLab.unity` if Unity does not switch to it automatically.
5. Press **Play**.

Three survivors choose wood piles using policy priority and travel distance. A central reservation registry prevents two survivors from claiming the same pile. The overlay shows each survivor's current state and decision explanation.

The generated scene is a disposable test laboratory. Run the menu command again whenever a clean copy is useful.

## Run tests

1. Choose **Window > General > Test Runner**.
2. Select **EditMode**.
3. Choose **Run All**.

The initial suite covers exclusive reservations, owner-only cancellation, score ordering, and resource underflow protection.

## Reliability checkpoint

This update retains cargo when a task is interrupted, filters unreachable sources,
requires complete paths, checks proximity to an interaction point, releases all
owner reservations on cancellation, and retries failed sources after five seconds.
A worker that makes no progress for eight seconds cancels its trip. A disabled
worker retains cargo and resumes delivery on re-enable.

The overlay is larger and displays carried wood. Materials generated by the scene
builder are now saved as assets. Regenerate the lab once to get those persistent
materials; confirm replacement only if you do not need your existing lab edits.

### Local acceptance checks (not executed in the development workspace)

1. Run all 12 EditMode tests, then all 4 PlayMode tests in Test Runner.
   PlayMode tests build a temporary NavMesh and check conservation every frame,
   interrupted delivery, and recovery when an unreachable source moves back.
   They intentionally create no camera or visible meshes: the Game view can be
   blank or say "No cameras rendering". Watch the Test Runner results instead.
   A lifecycle test disables and re-enables the real worker component, verifying
   reservation release, retained cargo, and resumed delivery.
2. Generate the lab and press Play. All 16 wood should reach the stockpile.
3. While a survivor carries wood, disable its HaulWorker component in the
   Inspector. The overlay should still show cargo 1. Re-enable it and confirm
   delivery resumes.
4. Temporarily disable the Stockpile component while wood is being carried.
   Cargo must remain with workers; re-enable it and confirm delivery resumes.
5. While a source is reserved, destroy that source GameObject in Play Mode.
   Reservations must recover. Destroying a resource pile explicitly removes its
   remaining wood, so adjust the expected total for that destructive test.
6. Move one pile well outside the ground. Workers should skip it and complete
   reachable work. Move it back and allow the five-second retry delay.
7. Test a carved obstacle that cuts off a source. No worker should collect
   resources remotely at a partial-path endpoint.
8. Stop Play Mode, save the generated scene, reopen it, and check material colors.

Conservation rule: ground wood + carried wood + stored wood remains 16 in
non-destructive tests. Deleting an entire survivor currently deletes its cargo;
death/drop handling and save/load are not implemented in this checkpoint.

This is a hauling reliability checkpoint, not the shelter-construction milestone.
Construction follows after the local acceptance checks pass. The debug worker list
is cached at startup; runtime spawning is not part of this lab.

## Current boundary

This milestone proves job selection, reservation, hauling, delivery, and debugging visibility. It does not yet include player controls, needs, construction, saving, combat, or final art.
